# ADR 0001: 筋の伸び率をブラウザ内の MuJoCo と MyoFullBody で計算する

## 背景

前身の yoga-pose-3d は、ヨガの写真 1 枚から MediaPipe で姿勢を推定し、3D マネキンに移して筋肉を色付けしていた。写真の中で隠れた脚の前後が決まらない、関節の範囲を超えた姿勢が出る、といった問題で、正解ポーズとの一致度は平均 43% 前後から上がらなかった。

本来の目的は「特定のポーズのときに、どの筋肉がどれだけ伸びるかを見せる」ことで、写真からの復元は手段だった。そこで別プロダクトとして作り直した。

## 決定

- 見せるのは「伸ばされる筋肉」。力を出している筋肉は扱わない
- 上半身と下半身の両方を対象にする
- 筋骨格モデルは MyoFullBody（MyoHub/myo_sim、Apache-2.0、123 関節・416 筋・関節の可動域つき）
- 筋長は MuJoCo 公式の JS/WASM バインディング `@mujoco/mujoco` でブラウザ内で計算する。骨への巻き付きも MuJoCo の計算をそのまま使う
- ポーズは関節スライダーで作る。写真からの推定はしない

試作（#2）で、ブラウザの計算値が Python 版 MuJoCo と小数第 3 位まで一致すること、1 ポーズの計算が約 1 ms で済むことを確かめた。

## 捨てた案

- **写真から 3D を復元する（yoga-pose-3d の続き、SAM 3D Body への差し替え）**: 隠れた部位は推定の限界があり、目的に対して重い
- **OpenSim の Rajagopal 2016 全身モデル**: 筋肉が下肢の 80 本だけで、上半身に筋肉が無い
- **MS-Human-700**: 700 筋あるが、配布されていない（coming soon）
- **ヨガポーズを実測したデータセット MOYO をポーズ集として使う**: ポーズの供給源にすぎない。SMPL-X からの変換が要るうえ、非商用に限られる
- **経路点を直線で結んで筋長を近似する**: 骨への巻き付きを無視すると、関節を深く曲げたときに長さがずれる

## 変えてよい前提 / 壊すと危ない前提

- **変えてよい**: 色の段階、代表筋の顔ぶれ、スライダーの部位分け、固定ポーズの中身
- **壊すと危ない**:
  - 伸び率の基準姿勢（ADR 0002）。基準がずれると全筋の値が静かにずれる
  - サーバや GPU を使わないこと。構成の前提になっている
  - `public/models/myo/` は生成物で、手で編集しない。更新は README の手順で行う
