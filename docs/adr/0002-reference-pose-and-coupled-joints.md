# ADR 0002: 伸び率の基準姿勢は qpos0 に連動関節の計算を当てた姿勢にする

## 背景

MyoFullBody の 123 関節のうち 51 関節は、joint 型の equality 制約でほかの関節に連動する（背骨の各椎間、膝の並進、膝蓋骨など）。MuJoCo の `mj_forward` はこの制約を満たさないので、関節角度を入れただけでは連動関節が動かない。

さらに、モデル既定の関節値 `qpos0` 自体が、定数項 `c0` が 0 でない制約を 6 本満たしていない。`qpos0` をそのまま基準にすると、立位で大腿直筋が膝の巻き付き面を裏側から回り込み、基準長が 0.178 m（+33%）長く出る。膝を曲げると回り込みが消えるので「膝の屈曲で大腿直筋が縮む（0.829）」と、解剖学と逆の値になった（#11）。

最初はこれをモデルの経路の不具合と判断し、sidesite の調整で直す方針まで決めたが、ブラウザ実装（拘束を満たした基準を使っていた）の値と突き合わせて測り方の誤りだと分かった。

## 決定

- 基準姿勢は「`qpos0` に連動関節の多項式計算を当てた姿勢」とする。基準長はこの姿勢で測る
- 連動関節は `q_dep = qpos0_dep + Σ c_i · (q_src − qpos0_src)^i`（i = 0..4、係数は `eq_data` の先頭 5 個）で直接計算する。相手の無い制約は `qpos0_dep + c0` に固定する
- スライダーにするのは独立に動かせる 71 関節だけ。連動関節は出さない
- 関節の値は `setJointAngle` 経由で入れ、可動域でクランプしたうえで連動関節を計算し直す。プリセットの読み込みも同じ経路を使う

この基準で、右膝 90° のとき大腿直筋 1.118・中間広筋 1.194（伸びる）、大腿二頭筋短頭 0.730（縮む）となり、解剖学どおりになる。

## 捨てた案

- **`qpos0` をそのまま基準にする**: 上の理由で大腿直筋の値が逆になる
- **大腿直筋の sidesite を調整してモデルを直す**: 原因がモデルではなく基準姿勢だったので不要。取り込んだモデルを上流からずらすことにもなる
- **連動関節を `mj_step` の物理計算で解く**: 拘束は満たせるが、約 1 ms で終わる計算が重くなる
- **連動関節もスライダーにする**: 独立に動かすと制約を破った姿勢になる

## 変えてよい前提 / 壊すと危ない前提

- **変えてよい**: スライダーの部位分け、スライダーの初期値
- **壊すと危ない**:
  - 基準長は連動計算を当てた後の姿勢で測ること。`qpos0` に戻すと大腿直筋の値が静かに逆転する
  - 連動関節の計算は制約を格納順に 1 回だけ評価している。これは「連動元がそれ自体連動関節ではない」ことが前提（現行モデルでは該当 0 本）。モデルを更新したら確認し直す（#6）
  - 比や伸び率を測るときは、分母（基準）と分子（比較対象）が同じ条件（ここでは制約を満たす）を満たしているかを先に確かめる
